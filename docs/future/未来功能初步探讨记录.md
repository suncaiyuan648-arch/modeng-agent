## 0. 当前结论

本记录讨论未来可能实现的 Compound Workspace，重点以推广/投流方向验证平台扩展能力。当前形成十一个初步结论：

1. 一级领域入口管理 Project，而不是打开一次性“功能页”；AI 助手、图片、视频、推广都使用相同 Project 导航语义。
2. “推广”未来应成为 Platform Shell 内的 Project 领域分组，而不是聊天里的一张大型 Artifact；单个推广计划进入 Campaign Project Workspace。
3. Research、Content、Publish、Monitoring 首先作为 Campaign Domain 对现有 Tool/Capability 的组合，不复制 Runtime、Task、Asset、Model、Context 和 Billing。
4. Product SKU/Price Book 与 Observable Tool Runtime 对当前五种能力也有价值，已经进入主架构；Campaign Domain 本身尚未进入当前开发范围。
5. AI Credits、平台 Product Price、上游 API Cost、真实媒体广告预算是不同事实；External Spend 永远不进入 Credit Ledger。
6. 当前不实现 Campaign 表、自动发布、平台爬虫、广告代充值或监测连接器，只记录产品假设、边界、风险和进入条件。
7. Task Center 是跨 Project 的 Operation/Execution Tree 读模型，不是新的 Task 微服务；Conversation、Task Center 和 Admin 展示同一执行事实的不同密度。
8. 批量图片/内容的分片、并发、失败子集与渐进 Artifact 已进入通用 V2.4 基线，未来 Campaign 只组合它，不自建批处理队列。
9. Workspace 素材库是可靠事实源；Project 通过关联组织素材。PC 本地目录导出只是渐进增强，H5 以 ZIP Artifact/下载为回退。
10. 未来 Campaign 仍不新增基础模块；任何 Campaign Prototype 必须通过 Manifest、Work Package 和现有 Public Port 组合，禁止为赶进度跨表或绕过 Runtime/Task/Billing/Asset Owner。
11. Campaign 实施继续使用根 `AGENTS.md` → 最近模块 `AGENTS.md` → Manifest/Contract/Test 的渐进上下文链；不复制完整架构文档，也不另建 Campaign 专属大型 Skill。

主架构只记录跨业务仍然成立的 Deep Module 和 Contract。本记录允许讨论 Campaign 特有页面、数据和流程，但不能反向要求基础平台提前实现万能 Workflow、搜索、发布或监测引擎。

## 2. 产品交互的三个层级

| 层级 | 典型能力 | 主要界面 |
| --- | --- | --- |
| Level 1 Chat | 问答、总结、改文案 | Conversation + Composer |
| Level 2 Guided Skill | 生图、生视频、语音识别、未来轻量 PPT | Skill Card + Task + Artifact + Chat |
| Level 3 Compound Workspace | 推广、深度研究、视频剪辑、大型 PPT 项目 | Domain Workspace + Progress + Tool Tree + Artifacts + Chat |

`已冻结边界`：三个层级共享 Platform Shell、身份权限、Context、Operation、Task、Event、Tool、Asset、Model Supply 和 Billing。Level 3 可以有独立路由、导航和领域状态，不等于另起一套登录、聊天、队列和计费系统。

### 2.1 Project 成为三个层级的共同外壳

```text
Workspace
  -> Project（用户持续推进的一件事）
     -> Conversation（AI 交互上下文）
        -> Operation（一次用户请求）
           -> Execution Graph（执行树）
              -> TaskRun（后端尝试）
```

`已冻结边界`：Project 负责标题、领域、导航、最近活动和归档，不负责 Campaign 预算、渠道、指标等领域事实。Project 的 `active/archived` 是注意力生命周期；归档 Project 不取消正在运行的 Operation。通用 Project 先进入当前基线，未来 Campaign 通过 `campaign.project_id` 附着在 Project 上。

Project 与素材的关系采用关联而非复制：Resource/Artifact 仍属于 Workspace；`ProjectResource/ProjectArtifact` 组成项目素材视图。这样同一张品牌 Logo 可用于多个 Project，同时在全局素材库中只有一个规范事实。

### 2.2 Task Center 与 Execution Tree

Task Center 的产品层级固定为：

```text
Project
  -> Root Operation
     -> Execution Node / Step / ToolCall
```

它支持按领域、状态、Project/Conversation 和时间筛选，并能回跳到 `/project/{projectId}/conversation/{sessionId}?operation={operationId}`。用户看到的是执行树、进度、失败项和 Artifact；TaskRun、BullMQ Job、Worker、Credential 与 ProviderJob 只在内部 Admin 可见。

`已冻结边界`：Execution Graph 是 Agent Runtime + Task Engine 内部的有界 DAG，只表达依赖、有限并行、重试和并发，不建立 Campaign Workflow Engine 或可执行 DSL。未来研究中的并行搜索、报告汇聚和内容批量生成都复用它。

### 2.3 批量结果与跨端保存

未来 Campaign 可能一次生成多渠道、多尺寸内容。通用基线已经规定：Model Supply 暴露单请求输出上限；Batch Planner 生成有限节点；Task Engine 与 Provider/Credential limiter 控制并发；每个成功批次立即写 OSS 并成为 Project Artifact。部分成功使用 `completed + partial`，可只对失败 ordinal 发起新 Operation。

平台不承诺浏览器自动写入用户电脑。PC 可在兼容浏览器、HTTPS 和用户手势下使用 `showDirectoryPicker` 作为增强；H5 与不兼容浏览器依赖平台素材库和 ZIP Artifact。MDN 将该 API 标为非 Baseline、实验性、仅安全上下文且需要用户激活，因此不能作为核心保存路径：[MDN showDirectoryPicker](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker)。

## 3. 推广中心的信息架构

### 3.1 一级入口

候选 PC 主导航；每个领域下展示最近 Project，`+` 创建 Project 与主 Conversation：

```text
AI 助手  [+]  最近咨询 Project...
图片     [+]  最近图片 Project...
视频     [+]  最近视频 Project...
推广     [+]  最近 Campaign Project...
────────────
任务中心
素材库
历史
账户 / 积分
```

H5 使用“领域入口 -> Project 列表 -> Project Workspace”的逐层布局，领域对象和 API 不变。“推广”进入 Campaign Project 列表：

```text
推广 Project
├── 新建推广计划
├── 我的推广
│   ├── 草稿
│   ├── 研究中
│   ├── 待确认
│   ├── 内容制作中
│   ├── 发布中
│   ├── 监测中
│   ├── 已完成
│   └── 失败/需处理
└── 账户/授权提示（只显示业务需要的安全状态）
```

Campaign Project 列表卡候选信息：Project 名称、推广对象、Campaign 状态、目标渠道、最近更新时间和少量关键指标。列表不展示 Tool 调用细节，也不复制完整报告。

### 3.2 单 Campaign Workspace

首版候选控制在四个区域：

```text
[总览] [分析报告] [推广内容] [数据]

右侧/抽屉：问 AI
可展开区域：进度与 Observable Tool Tree
```

- 总览：目标、阶段、待处理 Approval、渠道建议和下一步。
- 分析报告：市场、竞品、搜索、平台适配和推荐理由 Artifacts。
- 推广内容：文章、标题、标签、图片、视频及版本关系。
- 数据：发布记录、指标快照、趋势和建议；没有数据连接器时明确显示缺失，而不是模型编造。
- 问 AI：解释报告、比较渠道、修改内容、发起新的关联 Operation。

`已冻结边界`：Campaign 不是 Conversation 或 Project 的投影。Conversation 可以引用 Campaign/Artifact，Campaign 通过 `project_id` 获得通用导航、归档、素材和任务中心能力，但 Campaign 状态仍由未来 Campaign Domain 自己维护。

## 4. 候选 Campaign Domain

只有进入真实实施阶段后才创建该业务模块。候选聚合如下：

| 聚合/实体 | 候选职责 | 不应承担 |
| --- | --- | --- |
| BusinessProfile | 店铺、品牌、商品、目标客群等用户可管理权威事实 | 模糊偏好 Memory、聊天摘要 |
| Campaign | `project_id`、推广对象、目标、状态、阶段、选择渠道、预算授权引用 | Project 导航字段、Tool 原始响应、Credit Ledger |
| ResearchRun | 一轮研究范围、问题集、Tool/Step/Artifact 引用 | 自己实现搜索队列和 Tool Runtime |
| ContentPackage | 某渠道的标题、正文、标签、Media Artifact 版本 | 复制图片/视频二进制 |
| Publication | 发布目标、账号引用、Approval、外部发布 ID、状态 | 保存平台密码/Token 明文 |
| MetricSnapshot | 某 Publication 在时间点的可验证指标 | 将模型估算冒充真实平台数据 |

候选关系：

```text
Workspace
  └─ Project（domain=CAMPAIGN）
      └─ Campaign（project_id 唯一）
          ├─ Conversation / Operations / Execution Graph（通用平台引用）
          ├─ ResearchRuns -> ToolCalls -> Research/Report Artifacts
          ├─ ContentPackages -> Text/Image/Video Artifacts
          ├─ Publications -> Approval + external post reference
          └─ MetricSnapshots -> Performance Artifact

BusinessProfile -> Campaign（版本化权威上下文引用）
```

BusinessProfile 通过 `AuthoritativeContextSourcePort` 向 Context & Memory 提供版本化事实。Memory 可以保存“偏好中国风、喜欢简短文案”，但不能覆盖店名、地址、联系方式和商品价格。

## 5. 候选业务流程

```text
1. Business Profile
   -> 用户查看/补齐权威资料

2. Campaign Intake
   -> 推广对象 / 目标 / 地区 / 预算意向 / 时间范围

3. Research Scope & Billing Quote
   -> 快速 / 深度 / 自定义
   -> 展开 Product SKU line items
   -> 用户确认并 Reserve credits

4. Research Operation
   -> AgentStep / Observable Tool Tree
   -> Web Search / Platform Search / Model Query / Analysis

5. Marketing Report Artifact
   -> 来源、结论、置信边界、推荐渠道

6. Channel Decision
   -> 用户选择渠道和内容范围

7. Content Quote
   -> 首次生成 / revision / included minor edit

8. Content Generation
   -> TALK + IMAGE + VIDEO + Asset
   -> 多渠道/多尺寸使用有界 Execution Graph 与 Batch Planner
   -> 每批结果渐进进入 Campaign Project 素材，不等待整批完成

9. Approval
   -> 最终内容、账号、渠道、可能的 External Spend 授权

10. Publish（未来）
    -> Publish Tool；幂等、可撤销能力按平台实际情况定义

11. Monitoring（未来）
    -> 外部指标快照，不用 Chat 消息代替事实表

12. Next Action
    -> AI 解释变化并建议下一步，由用户确认新 Operation
```

## 6. Billing & Credits 候选产品设计

### 6.1 四类经济事实

| 事实 | 示例 | 所属边界 |
| --- | --- | --- |
| Usage | 3 次搜索、2 次模型分析、生成 3 张图 | Meter/执行事实 |
| Upstream Cost | Google API、模型、外部 Tool 实际成本 | Model/Tool 执行产生，Billing 对账 |
| Product Price | “深度竞品分析”售价 298 credits | Product SKU/Price Book |
| Customer Credits | Reserve 298、Charge 272、Release 26 | Credit Account/Ledger |
| External Spend | 抖音广告预算 500 元 | 未来独立资金账户/账本 |

### 6.2 候选 SKU

以下 code 仅用于边界讨论，不是已发布价目表：

```text
campaign.research.base
campaign.research.search-engine
campaign.research.ai-engine
campaign.research.platform
campaign.report.generate
campaign.content.initial
campaign.content.revision
campaign.publish
campaign.monitoring
```

Google、百度、小红书等可成为某个 SKU 的 dimension 或更细 SKU，最终取决于成本结构和用户是否需要理解该差异。SKU 是计费单位，不是新 Agent。

### 6.3 套餐假设

- 快速分析：低价、少量来源、适合初步判断。
- 深度分析：更多来源、交叉验证、结构化报告。
- 自定义：高级用户自己选择研究范围。

套餐展开为 Billable Items 后生成明细 Quote。Tool 卡可以解释费用归属，但 Operation 只做一次 Reservation 和最终 Settlement，不让余额随每个 Query 跳动。

### 6.4 Retry 与 Revision

| 场景 | 候选计费原则 |
| --- | --- |
| Worker/System 恢复 | 不产生第二笔用户收费 |
| 同一 Provider 请求查询/恢复 | 不产生第二笔用户收费 |
| 冻结策略内 fallback | 沿用原 Quote；差价按 policy 处理 |
| 用户主动重新生成/重写 | 新 `user-revision` Billable Item |
| 小范围文字修改 | 可由 SKU policy 设为 included/free |
| 部分 Tool 完成 | 按 frozen partial-settlement policy 处理 |

`开放问题`：哪些修改属于 included minor edit，必须由产品与客服争议数据验证，不能交给 LLM 临场判断。

## 7. Observable Tool Experience

### 7.1 Tool Tree

```text
竞品研究（AgentStep）
├── 互联网搜索（ToolCall）
│   ├── Google
│   └── 百度
├── 内容平台研究（ToolCall）
│   ├── 小红书
│   └── 抖音
├── AI 交叉研究（ToolCall）
│   ├── Kimi
│   └── Logical Model B
└── 生成报告（ToolCall）
```

默认只显示阶段摘要；逐层展开后才显示公开 Query、结果计数、关键 Citation、耗时、状态和 BillingQuoteLine 解释。大量 ToolCall 使用分页/虚拟列表，不占满主 Conversation。

### 7.2 Public Trace 与 Internal Audit

Public Trace 可以显示：

- 用户能够理解的公开工具/来源名称。
- 经过脱敏的 Query 或输入摘要。
- 结果数量、关键来源/Citation、输出摘要和耗时。
- 失败的安全说明、是否系统重试、对应费用是否 included。

Public Trace 禁止显示：

- API Key、Cookie、内部账号、签名和认证参数。
- System Prompt、隐藏推理过程和模型 Chain of Thought。
- Provider Channel、中转地址、Credential Pool 和成本路由评分。
- 未经授权的个人数据、其他租户内容和完整原始响应。

Internal Audit 使用不同 DTO、Repository、加密、RBAC 与 retention。它不能通过 Public Event/Query 意外序列化。

OpenAI 对 Codex 的官方介绍提到实时进度，以及通过终端日志和测试输出提供可验证执行证据。本项目借鉴的是“让用户看到可验证行为证据”这一原则，不复制 Codex 的具体 UI，也不把隐藏推理公开给用户：[Introducing Codex](https://openai.com/index/introducing-codex/)。

### 7.3 有副作用 Tool

Publish Tool 必须在外部调用前展示：渠道、目标账号、安全内容摘要、Artifact version、可能费用/External Spend 授权和过期时间。用户 Approval 绑定这些 fingerprint；任何内容、账号或预算变化都使旧 Approval 失效。

## 8. External Spend

`已冻结边界`：真实广告费不是 AI Credits。

未来如果平台代管广告预算，需要单独研究：

- 法币账户、充值、退款、冻结、结算和对账。
- 支付牌照/资金合规、发票和税务。
- 渠道预算授权、每日/总额上限和双重确认。
- 媒体平台实际消耗与本平台记录的差异处理。
- 账号归属、代理关系、异常投放和停止机制。

在法律、支付和渠道协议没有完成专项评审前，系统最多记录用户的“预算意向”，不得代扣、代充或承诺广告效果。

## 9. 2C4G 与执行边界

业务流程长不等于本机计算重。如果搜索、模型、图片和发布主要调用外部 API，Node 负责 IO、编排、事件和持久化，现有通用 Worker 可以支持早期验证。

以下能力不得直接压进 2C4G Node API/Worker：

- 同时运行大量 Chromium/Playwright 浏览器。
- 绕过平台规则抓取抖音、小红书等站点。
- 本地 Embedding/视觉模型/视频转码。
- 大规模网页抓取、索引和全文搜索集群。
- 高频指标采集且没有平台官方 API/限流策略。

真实出现后，优先使用官方 API、托管能力、受限专用 Worker 或独立外部服务。是否拆服务由 CPU/内存/队列/团队边界指标决定，不因流程图节点多而提前微服务化。

## 10. 探索阶段与进入条件

### F0：问题与渠道验证

- 访谈目标用户，确认“推广中心”是否比纯 Chat 更易理解。
- 确认用户愿意提供哪些 Business Profile 信息。
- 调研搜索、内容平台、发布和指标 API 的合法可用性。
- 用人工服务验证报告结构和推荐是否有真实价值。

进入 F1 条件：目标用户愿意完成资料并为至少一种研究报告付费/使用积分。

### F1：人工/半自动 Campaign Prototype

- Campaign Project 列表/Workspace 原型，复用通用 Project Shell 与 Task Center。
- Business Profile 与 Campaign Draft。
- 人工或有限 Tool 生成 Marketing Report Artifact。
- 不自动发布、不代管广告预算。

进入 F2 条件：报告可重复、用户能理解来源和建议，投诉/错误边界可控。

### F2：Research Tools 与明细 Quote

- 少量合法 Search/Model Tool Adapter。
- Observable Tool Tree 与 Citation。
- Product SKU、套餐、Quote/Reserve/Partial Settlement。

进入 F3 条件：工具成功率、单位成本、报告质量和毛差达到预设门槛。

### F3：内容生成闭环

- 渠道内容包、首次生成/revision SKU。
- TALK + IMAGE/VIDEO 组合。
- Artifact 版本、审批和修改历史。

进入 F4 条件：用户能够在不依赖人工客服的情况下完成内容确认。

### F4：受控发布

- 仅接有正式 API/授权的渠道。
- 一次性 Approval、幂等发布、外部 ID 和失败恢复。
- 暂不承诺自动广告投放。

进入 F5 条件：账号授权、内容审核、撤回/失败处理和平台协议完成专项评审。

### F5：Monitoring 与下一步建议

- 可验证 MetricSnapshot。
- Performance Artifact 与趋势。
- AI 建议新 Operation，用户确认后执行。

External Spend 是否进入产品必须单独立项，不因 F5 自动获得实现许可。

## 11. 关键风险

| 风险 | 当前控制方向 |
| --- | --- |
| 搜索/平台数据合法性 | 优先官方 API；评审 ToS、robots、版权和个人信息 |
| 推荐结果不可靠 | Citation、来源时间、事实/推断区分、人工确认 |
| 自动发布误操作 | 一次性 Approval、内容/账号 fingerprint、幂等和审计 |
| 费用争议 | 明细 Quote、冻结 policy、retry/revision 分类、不可变 Ledger |
| 广告效果承诺 | 不承诺结果；事实指标与模型建议分离 |
| Tool Trace 泄密 | Public/Internal 双层 Schema、脱敏、RBAC、retention |
| 大量 Tool 淹没 UI | Step 聚合、折叠、分页、虚拟列表 |
| 批量内容压垮 Provider/队列 | Spec 单请求上限、受限 Execution Graph、Offer/Credential 限流、背压 |
| 部分成功导致素材或费用争议 | 渐进 Artifact、稳定 ordinal、completed+partial、失败子集重试和明细 Settlement |
| 浏览器本地保存承诺无法兑现 | OSS/素材库为真源；PC 渐进增强，H5/不兼容浏览器使用 ZIP Artifact |
| 2C4G 资源耗尽 | 外部 API、专用低并发 Worker、背压和容量指标 |
| Campaign 污染平台 | 业务域只组合公共 Ports，不向 Core 添加营销特例 |

## 13. 明确不做

- 当前不创建 Campaign 微服务、Campaign Engine 或通用 Workflow DSL。

- 当前不接 Google/百度/小红书/抖音搜索、发布或监测生产接口。
- 当前不运行批量浏览器爬虫或绕过平台限制采集数据。
- 当前不实现广告账户充值、代投、自动调预算和收益承诺。
- 当前不因未来 Campaign 修改首版五种 Capability 的交付顺序。
- 当前不将本记录中的示例 SKU、价格、页面和数据库字段视为产品承诺。
- 当前不承诺 H5/所有桌面浏览器自动写入用户本地目录；只承诺平台素材持久化与受控下载。
