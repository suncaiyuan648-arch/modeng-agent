# taojinshu-ai-sdk 目录、文件职责与注释规范

## 1. SDK 物理边界

首期不创建独立 npm 包，目标源码放在当前仓库内：

```text
src/taojinshu-ai-sdk/                         / 通用、跨 Agent、可跨端提取的 AI Runtime SDK
```

依赖方向只能是：

```text
taojinshu-ai-sdk -X-> pages / ai-agents / router / Element Plus / 业务 API
taojinshu-ai-sdk -X-> Vue / Pinia / DOM / window / uni / 具体 Renderer 组件
```

SDK 与 Conversation、UI、Application、业务 Agent 的完整依赖方向统一见
[跨模块契约与架构决策](../01-跨模块契约与架构决策.md)。本文件不定义其他模块目录。

## 3. 公共 API 与方法职责

以下是 v1 允许对应用层暴露的方法。未列出的方法默认视为内部 API，不得由页面直接使用。

### 3.1 Runtime

```ts
/**
 * 使用已注入的传输、持久化、注册表和平台端口创建一个 Agent Runtime。
 *
 * @param options Runtime 依赖、恢复策略和安全策略。
 * @returns 可启动、订阅、执行命令和销毁的单一 Runtime 门面。
 * @throws {AgentSdkError} 当必需端口缺失或版本不兼容时抛出。
 */
export function createAgentRuntime(options: AgentRuntimeOptions): AgentRuntime;

export interface AgentRuntime {
  /** 启动 Runtime，并按策略恢复持久化状态与未完成 Operation。 */
  start(): Promise<void>;

  /**
   * 分发一个用户命令；命令只表示请求，最终状态必须由后续事件确认。
   * @param command 已通过业务层构造的 v1 用户命令。
   * @returns 命令接收回执，不代表业务执行完成。
   */
  dispatch(command: UserCommand): Promise<CommandReceipt>;

  /**
   * 执行本地 Runtime 命令，不允许通过 Transport 发往服务端。
   * @param command 恢复、重新投影或刷新能力等本地命令。
   */
  execute(command: RuntimeCommand): Promise<void>;

  /**
   * 订阅只读 Runtime 快照。
   * @param listener 每次归约完成后接收同一时点的不可变状态。
   * @returns 取消订阅函数。
   */
  subscribe(listener: RuntimeStateListener): Unsubscribe;

  /** 返回当前只读状态；调用方不得持有并修改内部集合。 */
  getState(): ReadonlyRuntimeState;

  /** 停止订阅、刷新待写数据并释放平台资源；允许重复调用。 */
  dispose(): Promise<void>;
}
```

### 3.2 Transport

```ts
export interface AgentTransport {
  /** 发送用户命令并返回服务端接收回执。 */
  send(command: UserCommand, signal?: AbortSignalLike): Promise<CommandReceipt>;

  /** 从指定序列后订阅 Operation 事件；断线策略由实现负责。 */
  subscribe(request: EventSubscriptionRequest): AsyncIterable<unknown>;

  /** 补拉闭区间内的事件，用于检测到序列空洞后的恢复。 */
  replay(request: EventReplayRequest): Promise<readonly unknown[]>;

  /** 主动关闭指定 Operation 的本地传输资源，不等同于业务取消。 */
  close(operationId: OperationId): Promise<void>;
}

/** 可注册到 AgentAdapterRegistry 的可信本地 Adapter 定义。 */
export interface AgentAdapterDefinition {
  /** 该 Adapter 服务的 Agent 类型。 */
  readonly agentType: string;
  /** 稳定 Adapter 标识，例如 geo.mock、geo.legacy、geo.v1。 */
  readonly adapterKind: AdapterKind;
  /** Adapter 真实支持的控制和恢复能力。 */
  readonly capabilities: AdapterCapabilities;
  /** 创建该路由对应 Transport；不得读取页面实例。 */
  createTransport(context: AdapterCreationContext): AgentTransport;
}

/** 仅管理本地可信 AdapterDefinition 的注册表。 */
export interface AgentAdapterRegistry {
  /** 注册定义；相同 agentType + adapterKind 重复注册必须拒绝。 */
  register(definition: AgentAdapterDefinition): void;
  /** 解析指定稳定标识；未知定义抛出 ADAPTER_NOT_FOUND。 */
  resolve(agentType: string, adapterKind: AdapterKind): AgentAdapterDefinition;
}

/** 为新 Operation 选择一次路由，并为旧 Operation 读取冻结路由。 */
export interface TransportRouter {
  /** 根据可信定义、Flag、后端描述和平台能力选择新路由。 */
  selectForNewOperation(input: TransportSelectionInput): Promise<OperationRoute>;
  /** 从 Operation/Snapshot 恢复冻结路由，不重新求值 Feature Flag。 */
  restore(route: OperationRoute): AgentTransport;
}
```

### 3.3 Registry 与投影

export interface SchemaRegistry {

export interface EventRepository {

## 4. 完整中文注释强制规范

### 4.1 必须注释的对象

SDK 中以下对象全部必须使用完整中文 TSDoc，不允许只写行尾短语：

- 每个 `.ts` 文件的文件头：职责、边界、主要依赖和禁止事项。
- 每个导出的 type、interface、class、enum、const、function。
- 每个 interface/type 的字段，包括联合类型中每种 payload 的字段。
- 每个类的构造函数、public/protected/private 方法和访问器。
- 每个顶层函数、回调工厂、Reducer、Projector、Codec 和 Adapter 方法。

### 4.2 注释内容

方法注释至少说明：

1. 业务语义和职责边界。
2. 每个参数的含义、单位、空值语义和是否已校验。
3. 返回值代表“已接收”还是“已完成”。
4. 可能抛出的 `AgentSdkError` 类别。
5. 幂等、顺序、重试、持久化或平台限制（如适用）。

禁止以下无信息注释：

```ts
/** 获取数据。 */
function getData() {}

/** 处理事件。 */
function handleEvent() {}
```

合格示例：

```ts
/**
 * 将已通过 Schema 校验的单个 Operation 事件归约到不可变状态。
 *
 * 本函数不执行网络、存储和日志副作用；重复输入相同状态和事件必须得到
 * 结构等价的结果。事件序列不连续时抛出 `SEQUENCE_GAP`，由上层恢复协调器补拉。
 *
 * @param state 归约前的只读 RuntimeState。
 * @param event 已解码且与当前协议 major 兼容的标准事件。
 * @returns 归约后的新 RuntimeState；不会修改传入对象。
 * @throws {AgentSdkError} 序列空洞、非法状态转移或实体归属冲突时抛出。
 */
export function reduceEvent(
  state: ReadonlyRuntimeState,
  event: AgentEventEnvelope,
): RuntimeState;
```

### 4.3 自动门禁

实施时新增通用 `scripts/check-ai-docs.mjs`，SDK 门禁通过作用域参数只扫描 `src/taojinshu-ai-sdk/**`：

- 文件缺少文件头注释则失败。
- 导出声明、字段或任何方法缺少 JSDoc/TSDoc 则失败。
- 公开方法缺少 `@param`、`@returns` 或声明存在抛错却缺少 `@throws` 则失败。
- 出现无法执行的待办描述或“获取数据”“处理逻辑”等无信息注释则失败。
- CI 顺序固定为：注释检查 -> `vue-tsc --noEmit` -> SDK 单测 -> conformance tests -> 应用回归测试 -> build。

首期可以使用自有检查脚本，稳定后再评估 `eslint-plugin-tsdoc` 和 API Extractor；不能因工具尚未引入而放宽注释验收。

业务 Agent、Conversation 与 UI 应使用各自独立的同等级注释门禁，不由 SDK 检查脚本越界扫描。

## 5. 提取为独立包后的入口

未来发布时保留以下入口，避免消费者加载不相关平台代码：

```text
@taojinshu/ai-sdk                    / 纯 TypeScript Core 和公共协议
@taojinshu/ai-sdk/platform-web       / Web Transport/Persistence 端口实现
@taojinshu/ai-sdk/platform-uni       / uni-app Transport/Persistence 端口实现
@taojinshu/ai-sdk/testing            / Fixture 与 conformance suite
```

各入口必须是显式 exports map，禁止消费者深层导入内部目录。
