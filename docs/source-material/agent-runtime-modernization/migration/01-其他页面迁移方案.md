# 其他页面接入与迁移方案

## 1. 迁移原则

- 每次只迁移一个可独立验收的 Operation，不按整个页面一次替换。
- 先加 Adapter 和 Characterization Tests，再替换数据源，不改视觉交互。
- 页面只能依赖 Agent Facade/ViewModel，不能依赖 Event payload、Transport 或 Legacy DTO。
- 未迁移功能继续走旧 Store/API；同一业务实体不得新旧双写。
- 每个 Agent 至少注册一个 Artifact Schema，验证 SDK 没有被 Geo 特化。

## 2. 通用迁移模板

```text
现有 Page / Store / API
  1. 盘点现有 DTO、状态、流式事件、文件、结果、取消和恢复
  2. 用 Characterization Tests 锁定现状
  3. 定义业务 Domain、AgentDefinition、Input/Artifact Schema
  4. 编写 Legacy Adapter -> v1 Event
  5. 编写 Agent Projector -> 页面 ViewModel
  6. 让 Facade 在 Feature Flag 下选择旧实现或 Runtime
  7. 替换一个纵向切片的数据源
  8. 验证刷新、重连、取消、错误、部分成功和双端 UI
  9. 灰度稳定后删除该切片的旧状态写入口
```

## 3. 接入优先级

### 第二个 Agent：PPT

Geo 首切片完成后优先 PPT，而不是继续抽象所有能力。PPT 能验证文件 Workspace、长 Operation、消息流、多个 Artifact 版本、预览/下载 Intent 和大对象持久化。

建议首切片：上传资料 -> 生成大纲 Operation -> outline Artifact -> 用户确认 -> 创建 PPT Operation。PPT 的 Document、Slide、Theme 和 Outline 位于 `src/ai-agents/ppt/`，不进入 SDK。

### 第三个 Agent：数字人/视频

验证长时异步任务、App 后台恢复、阶段进度、多个子任务、视频 Artifact、审核失败和部分成功。首切片只迁移“提交生成 -> 轮询/事件 -> 视频 ready”，不同时迁移素材编辑器。

### 第四个 Agent：选品/商品详情

验证列表型 Artifact、表格/卡片 Renderer、批量 Tool Call、外部来源和多 Artifact。Product、Market、Supplier 是业务 Domain。

### 最后迁移：通用 Chat

现有 Chat 链路复杂且回归面最大，应在 Geo/PPT/数字人验证协议后迁移。先迁移 Message ContentBlock 和单一流式 decoder，再处理工具调用、法律引用、图片/视频等 Renderer。

## 4. 迁移映射

| 旧实现 | 新实现 | 迁移完成判定 |
| --- | --- | --- |
| 页面直接 `api.xxx()` | Agent Facade `dispatch()` | 页面无业务 API import |
| 页面解析 SSE/chunk | Transport + EventCodec | 页面无流解析分支 |
| Pinia 写任务 status | Runtime Reducer | Store status 只读 |
| `result.url` | Artifact + ResourceLocator | 下载/预览走 Intent |
| `content:any` | ContentBlock/Schema data | Renderer 有强校验 |
| 页面组件 switch type | Renderer Registry | 后端不认识组件名 |
| sessionStorage 整对象 | Snapshot/EventRepository | owner 隔离和恢复测试通过 |
| `loading:boolean` | Command pending + Operation status | 并行 Operation 不互相覆盖 |

## 5. Agent 目录模板

```text
src/ai-agents/<agent-name>/                 / 单个业务 Agent 插件
├── index.ts                               # 稳定导出
├── domain/                                / 业务领域模型
├── contracts/                             / 当前后端 DTO
├── adapter/                               / Legacy/v1 Adapter
├── definition/                            / AgentDefinition 与 Projector
├── schema/                                / Input、Event 扩展和 Artifact Schema
├── renderer/web/                          / Web 业务 Renderer
├── renderer/uni/                          / uni-app 业务 Renderer
└── testing/                               / Fixture 与 conformance tests
```

每个目录和文件遵循 [SDK 目录与注释规范](../sdk/02-目录与文件规范.md) 的完整中文 TSDoc 原则；业务 Agent 使用独立检查范围，不能由 SDK 脚本越界扫描。

## 6. 旧接口兼容生命周期

```text
Stage A：旧页面 + 旧 Store + 旧 API
Stage B：旧页面 + Agent Facade + Legacy Adapter + Runtime
Stage C：新 ViewModel + Schema Renderer + Legacy Adapter
Stage D：新 ViewModel + Schema Renderer + v1 Adapter
Stage E：删除该切片旧 Store/API/DTO
```

Legacy Adapter 的删除门禁：后端 v1 灰度 100%、连续两个版本无回退、旧接口调用量为零、v1 与 Legacy conformance 最终状态一致、历史未完成 Operation 已清零或可继续使用旧 Adapter。

## 7. 路由与移动端

- 迁移不改变当前 `/chatAi/` 路由契约。
- PC/mobile 差异大时继续保留 `pc.vue`/`mobile.vue`，二者消费相同 ViewModel。
- 路由页面保持单根节点，避免 Layout transition 白屏。
- iOS/Android 的后台、键盘、文件、音视频和安全区由平台层/页面层处理，不进入 Core。
- uni-app Renderer 不是 Web Renderer 的 CSS 变体，复用 Schema/RenderModel，组件可独立实现。

## 8. 每页验收清单

- [ ] 页面和组件没有 import Transport、EventCodec、Legacy DTO。
- [ ] 页面不直接写 Operation/Artifact 状态。
- [ ] 正常、失败、取消、重试、断线、刷新、部分成功有测试。
- [ ] Feature Flag 可整切片回退，Operation 中途不换 Adapter。
- [ ] Web PC/mobile 和目标 uni-app 端语义一致。
- [ ] 所有新增 SDK/Agent 文件、字段、方法有完整中文注释。
- [ ] 原有路由切换链路和业务测试未回归。
