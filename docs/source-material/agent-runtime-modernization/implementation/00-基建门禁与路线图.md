# AI Agent 基建门禁、实施路线图与验收

> 本文件保留阶段门禁定义；多人施工的实际拆包、Conversation Layer、Web UI 和 QA 责任以
> [施工总控台](./README.md) 为准。

## 1. 开工前必须冻结

下列内容未评审通过前，不进入业务编码：

- Workspace/Session/Operation/Artifact 归属与 ID 规则。
- Operation 和 Artifact 状态机。
- User/Runtime Command 边界。
- Event Envelope、sequence、因果、未知事件和版本规则。
- Reducer 是唯一领域写入口。
- Snapshot/Replay/Retention 和跨 owner 隔离。
- Schema Registry、Renderer 和 UI Intent 安全边界。
- SDK/Agent 目录依赖方向与完整中文注释门禁。

逐文件、逐测试、逐提交的计划已经生成，但经源码核验后发现原 v1 契约仍有阻塞项。
先按 [Contract v1.1 开工冻结](./CONTRACT-V1.1-GATE.md) 完成 `design-v1.1-frozen`，仅放行测试底座和
WP0 Contract PR；标记 `contract-v1.1-frozen` 后才放行 Kernel 和满足各自依赖的后续工作包。

## 2. Phase 0：协议与 Kernel

### 产物

- `core/contracts`、`domain`、`protocol`、`errors`、`ports`。
- Operation/Artifact State Machine。
- `createInitialState()`、`reduceEvent()`、EventCodec。
- MockClock、MockIdGenerator、MockTransport、Fixture。
- SDK 注释检查脚本和依赖边界检查。

### 门禁

- v1 类型没有 `any`。
- Decoder 以 `unknown` 为入口。
- Reducer 纯函数、输入冻结测试通过。
- 状态转移、重复事件、序列冲突和空洞测试通过。
- 所有文件、声明、字段和方法有完整中文注释。

## 3. Phase 1：Message Kernel 与 Mock Geo 状态切片

### 产物

- 单一 AgentRuntime 门面、CommandBus、EventProcessor。
- `MessageContentBlock`、稳定 blockId、Message Event 与 Legacy Chat Adapter。
- Pinia 只读桥接、Geo AgentDefinition、Geo Projector。
- 研究 Operation 的 Mock Event Stream。
- ResearchProgress 使用新 ViewModel。

### 门禁

- 页面不解析事件、不写研究 status。
- Message delta、停止、未知 Block 降级和 Legacy Chat Fixture 通过。
- Geo normal/platform-failure/cancel/duplicate/out-of-order Fixture 通过。
- Feature Flag 关闭可回退旧研究链路。

## 4. Phase 2：Conversation、Artifact 与 Renderer

### 产物

- Schema Registry、Render Schema、UI Intent。
- ConversationProjector、ComposerController、ViewportController。
- `geo.research-report@1` 和 Web Renderer。
- Artifact State Machine 和部分成功展示。

### 门禁

- 未注册/不兼容 Schema 安全降级；SDK 不持有 Vue 组件 Registry。
- 伪造 Intent、危险 URL 和原始 HTML 安全测试通过。
- 当前 ResearchReport 视觉和交互无回归；真实聊天滚动、IME 与停止行为通过组件测试。

## 5. Phase 3：Persistence 与 Recovery

### 产物

- EventRepository、SnapshotRepository、RecoveryCoordinator。
- Web IndexedDB 迁移、单写提交队列、多标签页 leader 和内存降级实现。
- Mock/v1 支持 replay、实时流中断和 polling 回退；Legacy 进行中刷新仅标记 interrupted/non-resumable。

### 门禁

- 刷新、断网、事件空洞、毒事件隔离、并发冲突、损坏 Snapshot、跨账号切换测试通过。
- 已消费 Event 不重复投影，Artifact 不重复创建。
- Persistence 失败时明确显示 memory-only 能力降级。

## 6. Phase 4：Geo Legacy/真实接口

### 产物

- 当前 Geo DTO 的 Legacy Adapter。
- 后端 v1 可用后的 v1 Adapter。
- 同一 conformance suite 和灰度开关。

### 门禁

- 两种 Adapter 对共同支持的场景生成语义等价 RuntimeState；能力差异必须通过 capability 显式表达。
- 每个 Operation 冻结 Adapter 类型。
- 后端异常、鉴权、v1 取消竞态、Legacy 不可取消和部分平台失败可解释。

## 7. Phase 5：uni-app Core 验证

先不实现所有业务 UI，只验证：uni transport、uni persistence、App/小程序生命周期、Geo 研究状态 ViewModel 和一个报告 Renderer。H5、App、微信小程序分别运行 conformance suite；chunk 不可用端必须验证 polling。

## 8. Phase 6：PPT 验证与 SDK 提取评估

PPT 首切片通过后复盘：通用 SDK 是否出现 Geo/PPT 业务词、公共 API 是否稳定、跨端包体和依赖是否可控。只有达到 README 的提取条件才迁移 `packages/` 并设计发布流程。

## 10. CI 命令与顺序

实施后新增并执行：

```bash
pnpm check:ai-sdk-docs
pnpm check:ai-boundaries
pnpm exec vue-tsc --noEmit
pnpm exec vitest run src/taojinshu-ai-sdk src/ai-agents/geo-ad
pnpm test
pnpm build
```

现有测试若输出未导致失败的 TypeError/Vue warning，应单独登记为基线问题，不能在 SDK 任务中静默扩大或借机无关重构。

## 11. 灰度与回滚

- Flag 维度：环境、平台、用户分群、Agent、Workspace。
- 顺序：开发 Mock -> 测试环境真实接口 -> 内部用户 -> 5% -> 20% -> 50% -> 100%。
- 观察：协议错误率、重连率、恢复失败率、命令重复率、Renderer 缺失率、业务完成率。
- 回滚：只影响新创建 Operation；进行中 Operation 按创建时 adapterKind 继续或只读恢复。
- 数据：回滚不删除 Event/Snapshot，待稳定后按保留策略清理。

- [ ] 依赖边界、TypeScript、单测、集成测试、现有回归测试和构建通过。

## 13. 计划拆分建议

正式执行计划已经按可独立签收的工作包拆分：

1. `SDK Contracts + Runtime Kernel`。
2. `Message Kernel + Conversation Kit`。
3. `Geo Mock 状态纵向切片`。
4. `Artifact Renderer + Intent`。
5. `Application + Web UI`。
6. `Persistence + Recovery + Legacy Adapter`。
7. `uni-app Port + UI`。

每份计划使用 TDD：失败测试 -> 最小实现 -> 单项验证 -> 小提交；后端另立计划且需用户再次授权。
