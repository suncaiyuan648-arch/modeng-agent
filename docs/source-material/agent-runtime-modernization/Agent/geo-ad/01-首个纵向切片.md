# Geo Ad Agent 首个纵向切片

## 1. 选择范围

Geo 已有完整页面骨架、Phase A–H 设计页面、MockGeoAdApi、Pinia Store 和测试，适合作为首个真实业务接入；但当前 `createGeoAdApi()` 仍固定返回 Mock，实现中 `campaign.status`、`currentStep`、`activeView` 和路由 query 共同影响页面。

首条纵向切片只覆盖“客户搜索研究”：

```text
创建研究 Operation
  -> Mock/Legacy Event Stream
  -> Runtime Reducer
  -> Pinia 只读投影
  -> 研究进度
  -> geo.research-report@1 Artifact
  -> 刷新/断线恢复
```

不在此切片迁移资料上传、内容生成、报价、正式投放、发布跟踪和历史列表。

## 2. 状态映射

| 当前字段/行为 | 新模型 | 处理方式 |
| --- | --- | --- |
| `CampaignStatus.RESEARCHING` | `Operation.status=running` + `phase=researching` | Adapter 映射 |
| `RESEARCH_READY` | `Operation.status=completed` + Artifact ready | 由标准事件确认 |
| `ResearchPlatform.status` | AgentStep/ToolCall View | Geo Projector 投影 |
| `campaign.currentStep=research/report` | 页面导航 ViewModel | 不进入 Runtime Domain |
| `activeView=C03/C04` | 页面视觉状态 | 从 ViewModel + 路由一次性推导 |
| `researchReport` | `geo.research-report@1` Artifact | Schema 校验后渲染 |
| `loading/errorMessage` | Command pending / Operation error | Runtime/Pinia 投影 |

迁移后，研究链路的领域真相只来自 Runtime；现有页面的其他阶段仍由旧 Store 管理。两者通过明确的 facade 共存，禁止双写同一个研究字段。

## 3. 分阶段实施

### Phase 0：基建门禁

产物：IDs、Workspace/Session/Operation、Event Envelope、Codec、State Machine、Reducer、MockClock、MockTransport、conformance suite、注释检查。

验收：纯 TypeScript 测试可完成 `created -> running -> completed`，非法转移、重复事件和序列空洞均有确定结果。

### Phase 1：Mock 研究状态链路

只实现：

```text
operation.start.request
-> operation.created
-> operation.started
-> operation.phase.changed(researching)
-> agent-step.started/progress/completed
-> operation.completed
```

页面先替换 `ResearchProgress` 的数据来源，不加入 Artifact、Persistence、真实接口。这样优先验证 Contract、Event、Reducer 和 Pinia 投影。

验收：正常、平台失败、取消、乱序、重复事件五类 Fixture；研究页面不直接调用 `startResearch()` 修改 campaign。

### Phase 2：Artifact 与 Renderer

加入 `geo.research-report@1`、Artifact 生命周期、Web Renderer 和 Unsupported fallback。保留现有 `ResearchReport.vue` 的视觉能力，但通过薄包装接收 `GeoResearchReportViewModel`，不再直接读取旧 DTO。

验收：报告 ready、报告 failed、Operation 部分成功、未知 Schema、Schema 版本不兼容。

### Phase 3：Persistence、Replay、Recovery

加入 WebPersistence、Snapshot、Event delta 和轮询/SSE 模拟断线。刷新后先显示已恢复状态，再补拉新事件；不得重复进度或 Artifact。

验收：研究中刷新、完成后刷新、事件空洞、损坏 Snapshot、跨账号切换。

### Phase 4：Legacy Adapter 与真实 Geo 接口

当前后端未提供标准 Geo 协议时，在 `src/ai-agents/geo-ad/adapter/geo-legacy-adapter.ts` 内转换。页面不能感知当前/未来后端差异。后端提供 v1 后改用 `geo-v1-adapter.ts`，两者通过同一 conformance tests。

验收：同一 Fixture 经两种 Adapter 得到语义等价的最终 RuntimeState。

### Phase 5：扩大 Geo 覆盖

按独立 Operation/Artifact 逐步接入：

1. 资料识别：Resource + user-input-required。
2. 内容生成：多 Artifact、多版本 revise。
3. 报价确认：expectedVersion + entitlement/authorization。
4. 投放提交：幂等 Command + 平台子 Operation。
5. 发布跟踪：父子 Operation、部分成功和恢复。

## 4. 页面兼容策略

新增应用 Facade：

```text
GeoAdDeliveryPage
  -> useGeoAdResearchFacade
       ├─ 新 Runtime：研究 Operation、steps、report Artifact
       └─ 旧 Store：尚未迁移的 profile/material/content/delivery
```

Facade 对页面提供 `startResearch/cancelResearch/retryPlatform/researchView`。页面不得同时调用旧
`store.runResearch()` 与新 Runtime。Feature Flag 关闭时整条研究链路通过 bootstrap 注入的
`LegacyGeoResearchPort` 回退当前实现，Application/Agent 不直接 import 旧 Store，且不能在一次 Operation 中途切换实现。

## 5. Geo ViewModel

ViewModel 固定包含：`operationId/status/phase/progress/platformSteps/reportArtifact/partialSuccess/error/availableIntents/recoveredAt/canStart/canCancel`。progress 使用 0–1；`canCancel` 必须由 AdapterCapabilities 决定。`activeView` 的唯一映射：running/researching -> C03，completed + report ready -> C04；用户主动查看 C05/C06 是路由展示，不回写 Operation。

## 6. 测试范围

- Unit：Geo DTO Normalizer、Projector、Schema、Intent。
- Contract：MockTransport、LegacyAdapter、未来 v1 Adapter。
- Integration：Command -> events -> Runtime -> Pinia -> ResearchProgress/Report。
- Recovery：Mock/v1 验证刷新、断网和轮询；Legacy 只验证 interrupted/non-resumable 降级。
- Existing regression：Phase A–H 路由切换、PC/mobile 单根节点、现有 Geo 测试全部保留。

## 7. 回滚

按 Workspace 创建 Operation 时冻结 adapterKind；旧 Operation 使用原 Adapter 完成。灰度异常时关闭 `ai-runtime.geo.enabled`，新任务回到旧 Store；已由 Runtime 创建的 Operation 仍可只读恢复和展示，不能把 RuntimeState 反向写成旧 campaign 状态。
