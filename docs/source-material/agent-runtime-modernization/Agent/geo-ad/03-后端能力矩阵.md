# Geo Adapter 后端能力承诺矩阵

## 1. 当前代码事实

当前 `GeoAdApi.startResearch()` 返回一次性 `Promise<ResearchResult>`，没有服务端 operationId、状态查询、事件补拉或取消接口；`createGeoAdApi()` 固定装配 Mock。页面 Store 在 Promise 完成后把 Campaign 写入 `sessionStorage`，这属于页面结果缓存，不等于后端 Operation 恢复。

## 2. 能力矩阵

| 能力 | Geo Mock Adapter | 当前 Geo Legacy 接口 | 未来 Geo v1 后端 |
| --- | --- | --- | --- |
| 客户端 operationId | 支持并可完整模拟 | 仅本地映射，服务端不知道 | 服务端回显并持久化 |
| 实时事件 subscribe | Mock AsyncIterable | 不支持 | SSE/WebSocket/轮询事件 |
| replay(afterSequence) | 可模拟 | 不支持 | 必须支持 |
| 服务端取消 | 可模拟 accepted/cancelled | 不支持 | 必须有 cancel Command 与确认 Event |
| 本地 Abort | 支持 | 只有接口显式接收 signal 时支持；startResearch 当前不支持 | 支持关闭连接，但不等于服务端取消 |
| 进行中刷新恢复 | 可模拟 | 不支持 | Snapshot + replay 后支持 |
| 完成结果刷新展示 | Mock Fixture 可恢复 | 仅页面 sessionStorage 缓存；关闭 Tab 后不承诺 | 服务端状态/Artifact 可重建 |
| polling fallback | 可模拟 | 无查询接口，不能轮询 | 必须支持 afterSequence 或 status cursor |
| Adapter route 恢复 | Snapshot 中恢复 geo.mock | 只能恢复为 interrupted/geo.legacy | Snapshot 中恢复 geo.v1 |

## 3. Legacy 降级语义

当前 Legacy Operation 在刷新、页面卸载或连接不可确认后必须进入：

```text
status: interrupted
error.code: LEGACY_OPERATION_INTERRUPTED
error.retryable: true
recoveryMode: non-resumable
```

不得展示“正在恢复”“已取消”或“后台继续执行”。用户可以创建新 Operation 重试；旧 Operation 保留诊断信息，不能继续复用原 operationId 发起扣费型请求。

如果 Promise 已完成且页面已持久化结果，可以导入为一个 `legacy-imported` 终态 Operation 和 ready Artifact；导入事件必须标记 source 为 local-cache，不能伪装成服务端 replay。

## 4. UI 能力约束

- `canCancel` 只在 AdapterCapabilities 声明 `serverCancel=true` 时显示业务取消；本地 Abort 使用不同文案“停止等待结果”。
- `canResume` 为 false 时，刷新前提示当前任务无法恢复。
- memory-only、local-cache 和 server-replay 必须显示不同恢复来源。
- Mock 能力只用于开发与测试，不进入生产能力声明。

## 5. 后端 v1 前置接口

真实进行中恢复至少需要：

```text
POST /operations                          / 创建并回显 operationId
GET  /operations/{id}                     / 查询状态和最新 cursor
GET  /operations/{id}/events?after=n      / 补拉事件
GET  /operations/{id}/stream?after=n      / 实时事件或正式 polling 替代
POST /operations/{id}/cancel              / 请求取消
```

在上述能力上线前，WP5 的 Legacy 验收不得包含“真实进行中恢复成功”和“服务端取消成功”。
