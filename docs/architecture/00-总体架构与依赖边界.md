# 00 冻结架构与依赖边界

> STATUS: NORMATIVE / FROZEN  
> Baseline: V2.5 / 2026-08-11

本文是开工时的短架构入口，不复制完整设计。未在本文展开的细节以根 `AGENTS.md` 和 [完整 V2.5 参考规范](../../React-Node-全栈Agent架构规范.md) 为准。

## 当前实施形态

```text
React Web
  -> Node API / Realtime Gateway
  -> Agent Runtime / Deep Modules
  -> Task Worker
  -> PostgreSQL + Redis/BullMQ + OSS + external model providers
```

- 模块化单体，暂不按 Capability 拆微服务。
- TALK 是首个纵向切片；IMAGE、VIDEO、AUDIO、SUMMARY 不并行抢跑。
- Phase 0 只建设仓库、门禁、Contract 和测试地基，不实现业务。

## 目录直接表达 Runtime Boundary

```text
apps/                     可运行、可部署的 Composition Roots
packages/shared/          极少量前后端共享 Contract/Kernel
packages/frontend/        浏览器交互与投影
packages/backend/         后端业务权威与 Deep Modules
packages/infrastructure/  PostgreSQL/Redis/BullMQ/OSS 等 Port 实现
```

允许方向固定为：

```text
apps/web -> frontend -> shared
apps/api|worker -> backend -> shared
apps/api|worker -> infrastructure -> backend public ports
```

禁止 `frontend -> backend|infrastructure`、`backend -> frontend|infrastructure` 和 `shared -> frontend|backend|infrastructure`。Infrastructure 只能实现 Backend Port，不能把业务策略下沉到 Adapter。

## 冻结的后端认知边界

1. Identity & Session
2. Workspace, Project & Conversation
3. Context & Memory
4. Agent Runtime
5. Task Engine
6. Event & Realtime
7. Model Supply
8. Resource & Asset
9. Billing & Credits
10. Platform Core

`domain-kernel` 是极小稳定语义包，不是第十一个业务模块。TALK、SUMMARY、IMAGE、VIDEO、AUDIO 是 Capability 插件，不拥有平台基础设施。

## 冻结的所有权与依赖规则

- 一份可变状态和一张业务表只有一个 Writer Owner。
- 跨模块只通过包根 Public Port、Command、Event 或不可变 Snapshot/Reference DTO。
- Capability/API/Worker 不直接依赖 Prisma、BullMQ 或 Provider SDK。
- PostgreSQL 是业务事实；Redis/BullMQ 不是第二事实源。
- Agent Runtime 拥有 Operation/Execution Graph 逻辑状态；Task Engine 只拥有 TaskRun、attempt、Lease 与 checkpoint。
- Event & Realtime 负责 envelope、sequence、outbox、delivery 和 replay，不定义他域业务语义。
- Model Supply、Billing、Resource 分别隐藏供应路由、计价账本和素材生命周期。
- 前端 Runtime Reducer 是运行态唯一写入口；页面不解析 SSE，不维护第二份领域事实。

改变一级模块、Owner、依赖方向、状态机、数据库/MQ/运行进程或一致性边界，必须先批准 ADR。普通 Work Package 不得顺手改变这些规则。
