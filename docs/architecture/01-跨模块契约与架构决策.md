# 01 冻结跨模块契约与变更规则

> STATUS: NORMATIVE / FROZEN  
> Baseline: V2.5 / 2026-08-11

本文冻结的是开工规则，不预测性定义全部业务 DTO。第一条 TALK Vertical Slice 所需 Contract 由后续 WP-003 在这些边界内冻结。

## 当前 Contract 真源

| 事实                                  | 真源                                          |
| ------------------------------------- | --------------------------------------------- |
| 仓库不变量与规则优先级                | 根/局部 `AGENTS.md`                           |
| 模块 Owner、依赖、公开入口、文件 Zone | `module.manifest.json`                        |
| 跨网络/序列化数据                     | `packages/shared/contracts` 中的运行时 Schema |
| 模块实际公开 API                      | 包根 `src/index.ts` 与 `package.json#exports` |
| 适配器行为                            | Public Port + Fixture + Conformance Suite     |
| 架构例外                              | 已批准 ADR/Contract Change Proposal           |

TypeScript 类型不能单独成为跨网络真源；外部数据必须从 `unknown` 开始，经运行时 Schema 验证后进入 Domain。

## 变更等级

- GREEN：模块内部实现、私有类型、模块测试和现有 Contract 后的 Adapter。
- YELLOW：Manifest、`index.ts`、Migration、共享 Fixture、Feature Flag/Retention；必须由 Work Package 明确授权。
- RED：Public Contract、状态机、Owner、依赖方向、owned table、protocol major；必须先批准 CR/ADR。

如果实现遇到 RED 变化，停止绕行并报告 `CONTRACT_CHANGE_REQUIRED`。CI 与行为测试是合并门禁，AI Review 只能提供补充判断。

## Phase 0 冻结范围

- WP-000：仓库骨架、工具链、空模块边界和可运行验证命令。
- WP-001：建立密钥与 API Key 保护基线，确保凭据不进入仓库、日志或前端。
- WP-002：用正反 Fixture 证明架构门禁有效。
- WP-003：只冻结 TALK 最小闭环需要的 Brand ID、Command/Event、Project、Operation、Execution Graph、TaskRun、Artifact Base 与 Platform Error。
- WP-004：使用 Fake Model 证明 TALK 端到端链路，不接真实 Provider。

完整 CR、ADR、Work Package 与 Conformance 规则见 [工程治理规范](../../AI工程治理与Work-Package规范.md)。
