# CR-0003: WP-005 Model Supply composition-only factory authorization

- Contract owner: `backend-model-supply`
- Requested by: WP-005 Real TALK Provider + Modeng Model Supply Foundation
- Current version: no WP-005 composition factory; `ModelExecutionPort@1` is the only approved Model Supply contract
- Proposed version: non-versioned package-root composition-only factory surface for WP-005
- Compatibility: additive-minor
- Compatibility note: additive non-versioned composition-only package-root surface; no versioned Contract or Port compatibility change
- Base: `main@6302e7f` (`6302e7f`)
- Status: `PROPOSED / PLANNING RECORD`
- Approval gate: repository-owner and architecture review approval, followed by merge to `main`, before WP-005 implementation
- Architecture review: `ADR required = NO`

## Authorization

This CCR authorizes only the following narrow package-root composition surface in
`packages/backend/model-supply/src/index.ts`:

- a non-versioned `resolveTalkExecutionPlan()` composition-only factory/function
  that resolves the existing `talk.default` assignment into an opaque existing
  `ModelExecutionPlanRefV1`; and
- a composition return containing the existing `ModelExecutionPort@1`
  implementation (`executionPort`) so the API composition root can inject both
  pieces into TALK.

The factory is an in-process composition seam, not a new cross-module stable Port.
Only the Model Supply owner interprets `planId`; consumers receive no release,
Offer, Channel, provider, model, credential, endpoint, raw response, or system
prompt fields.

This is a one-purpose authorization for WP-005. It does not authorize or freeze a
general resolver API, a `ModelSupplyResolverPort@1`, a new `@1` Port, a new schema,
or any change to `ModelExecutionPort@1` semantics.

## Problem

`CCR-0002` authorizes only `ModelExecutionPort@1` and explicitly excludes later
Port-surface expansion. It cannot be reused to authorize this additional
composition-only return surface. This CCR therefore records the smallest focused
exception required by the current package-root governance fact; it does not widen
Rules Lite, reclassify ordinary `index.ts` changes, or modify the architecture
guard.

## Proposed change

WP-005 keeps these existing surfaces unchanged:

- `ModelExecutionPort@1`, including its request, opaque plan reference, normalized
  stream, error codes, and abort semantics;
- `TalkSubmitCommand@1` and the existing Event/SSE schemas;
- Model Supply ownership of model assignment, plan identity, provider execution,
  credential boundary, and error normalization;
- the existing modular-monolith dependency direction and in-process composition.

The implementation may add the narrow factory only after this CCR and the WP-005
planning record are approved and merged. The implementation must continue to use
the package root; no consumer may deep-import `backend-model-supply/internal/**`.

The factory remains non-versioned and composition-only. It must resolve
`talk.default` to an immutable plan snapshot and then return the existing opaque
`ModelExecutionPlanRefV1`; `talk.default` must never be used as `planId`. The
implementation must not export a general resolver API, a
`ModelSupplyResolverPort@1`, Provider DTOs, or Model Supply binding objects.

The WP-005 plan separately owns the native `fetch`/internal transport seam,
DeepSeek bindings, SSE terminal handling, single-use plan cleanup, secret
handoff, and Web Local copy. This CCR grants no additional runtime
authorization for those changes.

## Compatibility and affected modules

- Public Contract: `ModelExecutionPort@1`, `TalkSubmitCommand@1`, and the
  existing Event/SSE schemas remain unchanged. This is an additive,
  non-versioned package-root composition surface, not a versioned Contract
  compatibility change.
- Owner: `backend-model-supply` continues to own model assignment, plan
  identity, provider execution, credential lookup, and error normalization.
- Consumer: `backend-capability-talk` may receive the injected composition
  result through the approved package-root seam. `backend-agent-runtime` and
  Event & Realtime retain their current lifecycle and event ownership.
- Package boundary: no deep import of `backend-model-supply/internal/**` is
  authorized; no new module, Owner, persistence table, dependency direction,
  Manifest architecture fact, or public Provider DTO is introduced.
- Runtime behavior: no Worker, queue, Redis, Prisma, Billing, migration,
  feature flag, retention policy, fallback routing, or external side effect
  is authorized by this CCR.

## Forbidden changes

This CCR must not be used to:

- add or modify a shared Contract, versioned Port, schema, Event/SSE field, or
  public request field;
- extend `CCR-0002` or introduce `ModelSupplyResolverPort@1`;
- export Provider DTOs, DeepSeek model aliases, ModelVersion/Offer/Channel
  objects, credential references, API keys, base URLs, raw responses, system
  instructions, or hidden reasoning;
- let TALK, API, the browser, or Agent Runtime interpret `planId` or own model
  assignment/binding state;
- modify the module owner, architecture guard, Manifest owner/dependency facts,
  migration, persistence, Worker/MQ handoff, Billing, fallback routing, or a
  new state machine;
- modify Rules Lite or reinterpret this CCR as a general permission for
  package-root Contract changes;
- add OpenAI SDK or a Provider SDK; the provider adapter remains an internal
  native-fetch/transport-seam implementation under the separate WP-005 plan.
- add a real DeepSeek key to the repository, planning PR, fixtures, logs, or
  browser-exposed configuration.

If implementation needs any forbidden change, stop and submit the appropriately
focused CCR or ADR instead of widening this record.

## Fixtures and conformance

This planning CCR changes no runtime code, dependency, database, configuration,
credential, or external system. After merge, the WP-005 implementation must prove:

1. `talk.default → immutable snapshot → execute` is preserved and `talk.default`
   is never used as `planId`;
2. the composition-only factory is only consumed through the package root;
3. the existing Fake and real adapter use the shared Model Execution conformance
   harness; and
4. no public trace or serialized Contract contains provider/model/credential,
   preamble, raw provider data, or hidden reasoning.

The WP-005 plan separately defines the DeepSeek bindings, native transport seam,
single-use plan cleanup, SSE terminal semantics, secret handoff, and browser copy.
Those are implementation scope, not additional CCR authorization.

## Architecture and ADR decision

`ADR required = NO` for this narrowly described composition seam because it
preserves the modular-monolith process, the existing Model Supply Owner, the
existing dependency direction, in-process composition, and the existing
cancellation boundary. It does not add a new process, queue, Owner, table,
state machine, user-visible cancellation Contract, or versioned Port.

Stop and request a focused CCR or ADR before coding if review or implementation
proposes a new versioned Port, a new persistence/consistency boundary, a
dependency-direction change, a Provider Contract beyond `ModelExecutionPort@1`,
or user-visible Operation cancellation.

## Migration / rollout / rollback

1. Review and merge this CCR and the approved WP-005 planning record to `main`.
2. Start the implementation branch from that `main`; do not implement from a
   planning branch whose CCR is not merged.
3. If the composition seam proves insufficient and a versioned cross-module Port
   is proposed, stop and submit a new focused CCR.

Before implementation, rollback is a documentation-only revert of this CCR. No
runtime, database, credential, provider, queue, or external side effect exists in
this planning record.
