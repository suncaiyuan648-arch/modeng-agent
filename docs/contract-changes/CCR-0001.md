# CR-0001: WP-003 Contract Kernel v1 frozen Contract

- Contract owner: shared-contracts (`@modern-agent/shared-contracts`)
- Requested by: WP-003 Contract Kernel planning record
- Current version: 0.0.0 bootstrap-only Contract
- Proposed version: 1.0.0 WP-003 Contract Kernel
- Compatibility: breaking-major
- Status: APPROVED / PLANNING RECORD

## Authorization

This record authorizes only the WP-003 v1 Contract surface described below,
after this record has been reviewed, merged to `main`, and included in the
implementation branch `BASE_SHA`. The current CCR planning diff authorizes no
implementation and does not change any implementation permission.

- `packages/shared/contracts/src/index.ts`

No other path under `packages/shared/contracts` is authorized by this CCR. The
WP-003 planning record remains the sole source for implementation paths and
forbidden scope.

## Problem

WP-003 needs a runtime-validated Contract Kernel for the first Fake TALK
vertical slice, but `shared-contracts` currently exposes only its bootstrap
module identity and has no business Contract. Changing the frozen shared
Contract without an approved CCR in `BASE_SHA` triggers `ARCH006`.

## Current contract

- `packages/shared/contracts/src/index.ts` exports only the bootstrap
  `SHARED_CONTRACTS_MODULE` constant.
- The package is version `0.0.0`; no business identifier, command, event,
  operation, graph, task, artifact, or platform-error Contract is currently
  defined.
- No owner, dependency direction, persistence model, provider behavior, queue
  behavior, billing behavior, or architecture boundary is changed by this
  record.

## Proposed change

Freeze exactly the WP-003 v1 Contract surface in the `shared-contracts` public
root. Fields not listed here or in the WP-003 planning record are not
authorized.

- Branded identifiers: `BrandId`, `ProjectId`, `OperationId`,
  `ExecutionGraphId`, `ExecutionNodeId`, `TaskRunId`, `ArtifactId`,
  `CommandId`, and `EventId`; every network envelope and versioned value has
  `schemaVersion: 1`.
- `ProjectRef`: `projectId`, `brandId`, and `domain: "TALK"`.
- `TalkSubmitCommand`: `schemaVersion`, `commandId`, `idempotencyKey`,
  `type: "talk.submit"`, `project`, and `input.text` with the WP-003 bounded
  length; no provider, model, or credential fields.
- `EventEnvelope`: `schemaVersion`, `eventId`, `operationId`, `sequence`,
  `occurredAt`, `type`, and `payload`, with only these v1 event types:
  `operation.accepted`, `talk.output.delta`, `operation.completed`, and
  `operation.failed`.
- `OperationRef`: `operationId`, `project`, `status`, `executionGraphId`,
  `createdAt`, and optional `completedAt`; statuses are `accepted`, `running`,
  `completed`, `failed`, and `cancelled`.
- `ExecutionGraphRef`: `executionGraphId`, `operationId`, `rootNodeId`, and a
  finite node list whose node fields are `nodeId`, `kind: "talk"`, and
  `dependsOn`; the WP-003 single-root, cycle, dependency, duplicate-ID, and
  size constraints apply.
- `TaskRunRef`: `taskRunId`, `operationId`, `nodeId`, `attempt`, and `status`;
  statuses are `pending`, `running`, `completed`, and `failed`.
- `ArtifactBase`: `artifactId`, `operationId`, `kind: "text"`, `status`,
  `schemaVersion`, and `createdAt`; statuses are `draft`, `ready`, and
  `failed`.
- `PlatformError`: stable v1 `code`, user-safe `message`, `retryable`, and
  optional bounded safe `details`; secrets, provider data, prompts, hidden
  reasoning, stack traces, and database details remain prohibited.

This change does not add any identifier, field, status, event, error code,
state transition, or semantic meaning beyond the WP-003 v1 surface above. It
does not define a Workflow DSL, transport-specific DTO, provider abstraction,
persistence model, or general capability schema.
